# 챕터 02 — 비트, 바이트, 숫자, 그리고 주소

> **Part I — A Computer That Can Run Code**

## 하나의 패턴, 여러 의미

챕터 01에서는 바이트 `0x41`을 따라갔습니다. 이 장에서는 같은 저장된 비트가 숫자, 문자, 플래그 집합, 주소가 어떻게 될 수 있는지 설명합니다. 각 해석을 계산하고, 어떤 연산이 어떤 해석을 요구하는지 알아낼 수 있어야 합니다.

비트는 0과 1 두 값을 가집니다. 바이트는 8비트를 담습니다. 부호 없는 바이트에서 비트 0의 가중치는 1, 비트 1은 2, 비트 7은 128입니다. 비트는 오른쪽부터 0으로 번호를 매깁니다. 따라서 `01000001`은 `64 + 1 = 65`를 나타냅니다. ASCII는 그 값에 `A`를 연결합니다 — 비트 자체는 "문자"라는 라벨을 담고 있지 않습니다.

16진수는 같은 패턴을 줄여 씁니다. 각 자릿수가 4비트를 나타내므로 `0x41`은 `0100`과 `0001`로 나뉩니다. 수치값은 `4 × 16 + 1`입니다. `0x` 접두사는 표기법을 지정할 뿐 저장된 값의 일부가 아닙니다. 십진수 `65`, 십육진수 `0x41`, 이진수 `0b01000001`은 모두 같은 부호 없는 정수를 기술합니다.

## 너비가 질문을 바꾼다

8비트에는 256개의 패턴이 있습니다. 부호 없는 해석은 이를 0~255에 배정합니다. 2의 보수 부호 있는 해석은 최상위 비트가 1인 패턴을 음수에 배정합니다: 부호 없는 값에서 256을 뺍니다. 따라서 `0xF0`은 240이거나 `240 - 256 = -16`입니다.

너비는 필수입니다. 16비트 패턴으로 보면 `0x00F0`은 양수 240입니다. 8비트 부호 있는 값을 넓힐 때 음수 16을 보존하려면 부호 비트를 새 자리로 반복해야 하며 `0xFFF0`이 됩니다. 영 확장(zero extension)은 새 자리를 0으로 채워 부호 없는 값을 보존합니다.

최상위 비트가 1인 n비트 부호 있는 값의 일반 규칙은 `unsigned_value - 2^n`입니다. 그 너비 안에서 모든 비트를 반전하고 1을 더하면 음수의 크기를 구할 수 있습니다. 어느 규칙도 저장된 패턴과 별개의 특수한 물리적 "음수 비트"를 요구하지 않습니다.

```text
8비트 패턴   부호 없음   부호 있음   부호 있는 값을 보존하며 16비트로 확장
01111111          127       127      007F
10000000          128      -128      FF80
11110000          240       -16      FFF0
```

산술에도 너비가 있습니다. 결과 8비트만 유지하면 `255 + 1`은 0이 됩니다. 이 하드웨어 사실이 모든 C 오버플로 표현식을 유효하게 만들지는 않습니다: 부호 없는 C 산술은 감기지만 부호 있는 오버플로는 언어 규칙이 다릅니다. 언어 규약과 선택한 기계 연산을 분리해 두세요.

## 플래그는 전체 숫자가 아니라 위치를 묻는다

상태 바이트가 `0xA5 = 10100101`라고 합시다. 다른 모든 것을 보존하면서 비트 2를 지우고 싶습니다. 마스크는 연산이 비트를 유지하거나 선택해야 하는 자리에 1을 둡니다.

```text
값            10100101   A5
유지 마스크    11111011   FB
AND 결과      10100001   A1
```

AND(`&`)는 두 입력 비트가 모두 1인 자리에서만 1을 줍니다. OR(`|`)는 둘 중 하나라도 1이면 1입니다. XOR(`^`)는 비트가 다르면 1입니다. 따라서 8비트 값에서 `0x04`와의 OR은 비트 2를 설정하고, `0xFB`와의 AND는 지우며, `0x04`와의 XOR는 토글합니다. 두 번 토글하면 원래 값으로 돌아오지만 두 번 지우면 지워진 채 남습니다.

비트 2가 설정됐는지 확인하려면 `(value & 0x04) != 0`을 씁니다. 대신 `value == 0x04`를 검사하면 비트 2가 *유일하게* 설정된 비트를 묻습니다. `0xA5`에서 첫 검사는 성공하고 두 번째는 실패합니다. 여러 하드웨어 이벤트가 하나의 상태 레지스터를 공유할 때 이 차이가 중요해집니다.

## 주소는 위치를 선택하는 데 쓰이는 숫자다

주소는 위치를 식별합니다. 거기에 저장된 값은 별개의 숫자입니다. 어떤 장치가 `0x10000000`에서 시작하는 범위를 차지한다고 합시다. 문서는 STATUS가 시작점에서 4바이트 뒤에 있다고 기술합니다. 그러면 주소는 `0x10000000 + 0x04 = 0x10000004`입니다. 그 주소에서 읽은 값은 `0xA5`일 수 있습니다; 주소에 4를 더한다고 값에 4가 더해지지는 않습니다.

오프셋은 인터페이스가 지정한 단위로 측정합니다. 이 장치 오프셋은 바이트입니다. C에서 `uint32_t *`에 1을 더하면 원소 하나(보통 4바이트)만큼 전진하고, 바이트 포인터에 1을 더하면 1바이트 전진합니다. 나중에 이 연산들을 명령어 수준 바이트 오프셋으로 옮기겠습니다.

이제 충분히 많은 표기를 갖게 되었습니다. 16진수 숫자가 스스로 설명한다고 가정하지 않고 메모리를 조사할 수 있습니다. 챕터 03은 빠진 질문을 더합니다: 어떤 바이트들이 하나의 값에 속하며, 어떤 순서입니까?

## 체크

1. 이미 0이었더라도 8비트 값의 비트 2를 지우는 연산은?
   - A) `0x04`와 XOR
   - B) `0xFB`와 AND
   - C) `0x04`와 OR
   - Answer: B
   - Explanation: AND는 그 자리를 강제로 0으로 만들고 나머지 7비트를 보존합니다. XOR는 토글하고 OR는 설정합니다.

2. 8비트 패턴 `0xF0`에 대해 옳은 진술을 모두 고르세요.
   - A) 부호 없는 값은 240입니다.
   - B) 부호 있는 값은 -16입니다.
   - C) 부호 있는 값으로 16비트 확장하면 `0x00F0`이 됩니다.
   - Answer: A, B
   - Explanation: 부호 있는 값을 보존하려면 `0xFFF0`이 필요합니다. 영 확장은 240을 보존합니다.

3. `0x80000005`를 부호 없는 32비트 정수와 부호 있는 32비트 정수로 각각 해석하세요. 그리고 각각의 해석을 값이 바뀌지 않도록 64비트로 확장하세요. 두 결과 패턴을 보이세요.
   > Hint: 부호 있는 결과는 부호 없는 결과에서 `2^32`를 뺀 값입니다.

4. 구성 바이트의 비트 6:4에 3비트 필드가 있습니다. 다른 모든 비트를 보존하면서 그 필드를 5로 대체하는 식을 유도하세요. 단순히 `5 << 4`를 OR 하는 것이 적어도 하나의 시작 값에서 실패하는 이유를 보이세요.

5. Research challenge: 디바이스 트리의 부모가 address cell 2개와 size cell 2개를 지정합니다. Devicetree 명세를 참고해 `reg = <0x0 0x10000000 0x0 0x1000>`을 해석하세요. 반열린 주소 구간을 제시하고, 어떤 추가 부모 정보가 주소 변환에 영향을 줄 수 있는지 설명하세요.

## 정확성의 경계

이 장의 비트 연산 예제는 명시적으로 크기가 정해진 부호 없는 값에 동작합니다. C의 승격과 부호 있는 시프트에는 자체 언어 규칙이 필요합니다. 장치 레지스터는 쓰기에 동작을 연결할 수 있어 RAM에 유효한 비트 조작이 자동으로 유효한 레지스터 갱신이 되지는 않습니다. 그 구분은 챕터 10에서 다룹니다.
