# 챕터 19 — 캐시와 메모리 계층 구조

> **Part V — Memory Becomes Virtual**

## 어떤 사본이 메모리 읽기를 공급하는가?

앞의 명령어 추적은 그 값들이 물리적으로 어디서 공급되었는지 설명하지 않고 아키텍처 값만 기술했습니다. 캐시는 최근에 쓴 메모리를 CPU 가까이 두어 많은 접근이 더 느린 하위 수준을 피하게 합니다. 핵심 질문은 어떤 사본이 유효한가, 어떤 사본이 더 새로운가, 어떤 관측자가 일관성 유지에 참여하는가입니다.

64바이트 라인을 쓰는 단순화된 write-back 데이터 캐시를 사용합니다. 라인은 이 캐시가 저장하고 추적하는 단위입니다. 주소 `0x2004`에 접근하면 정렬된 범위 `0x2000`부터 `0x203F`까지가 캐시로 들어올 수 있습니다. 요청한 바이트나 워드는 그 라인의 일부이며 이웃 바이트도 함께 도착합니다.

## 더티 라인 하나 따라가기

처음에 RAM의 `0x2004`에는 정수 7이 있습니다. CPU가 그것을 읽어 캐시된 라인을 얻습니다. 그다음 같은 위치에 9를 저장합니다. write-back 정책에서는 하위 메모리가 여전히 7을 담고 있는 동안 캐시가 9를 유지할 수 있습니다. 아직 기록되지 않은 수정 내용을 담기 때문에 라인은 더티입니다.

| 이벤트 | CPU 캐시 값 | 하위 메모리 값 | 상태 |
| --- | --- | --- | --- |
| 접근 전 | 없음 | 7 | 캐시된 라인 없음 |
| 읽기 미스 채움 | 7 | 7 | clean |
| CPU 저장 | 9 | 7 | dirty |
| writeback | 9 또는 이후 제거 | 9 | 하위 사본 갱신 |

관련 메모리 규칙 아래에서 이 CPU의 이후 load는 자신의 값 9를 봅니다. 비일관적 장치가 하위 메모리를 읽는다고 가정하면 writeback 전까지 7을 볼 수 있습니다. 그것이 같은 CPU의 평범한 load가 오래된 데이터를 무작위로 반환한다는 뜻은 아닙니다. 일관성 배치 밖의 특정 관측자를 식별한 것입니다.

더티 라인을 클리닝하는 것은 변경을 필요한 가시성 지점 방향으로 기록하는 것입니다. 무효화는 캐시된 사본을 제거해 이후 접근이 새 사본을 얻게 합니다. 필요한 변경을 보존하지 않고 더티 라인을 버리면 데이터를 잃을 수 있습니다. 아키텍처 특화 명령과 DMA API가 어떤 유지보수가 필요한지, 어디서 효과를 갖는지 정확히 정의합니다.

## 캐시가 대개 도움을 주는 이유

시간적 국소성은 최근에 쓴 데이터를 다시 쓸 가능성이 높다는 뜻입니다. 공간적 국소성은 가까운 주소가 함께 쓰일 가능성이 높다는 뜻입니다. 연속된 4바이트 원소를 순회하는 루프는 다음 라인으로 넘어가기 전에 한 64바이트 라인에서 16개 원소를 쓸 수 있습니다. 흩어진 포인터 체인은 유필드 하나를 위해 라인을 가져올 수 있어 그 이득이 줄어듭니다.

용량과 배치도 중요합니다. 캐시보다 큰 작업 집합은 유용한 라인을 밀어냅니다. 같은 제한된 세트를 두고 경쟁하는 주소는 결합 크기가 충분히 작아 보여도 미스를 일으킬 수 있습니다. 접근 횟수 추정치가 자동으로 캐시 미스 추정치가 되지는 않습니다.

CPU 간 일관성은 공유 메모리 사본을 조정합니다. 그것은 애플리케이션의 동기화 프로토콜과 다릅니다: 두 일관적 CPU도 챕터 17처럼 증가를 잃을 수 있습니다. 일관성은 여러 명령어를 하나의 원자적 트랜잭션으로 만들지 않으며, 모든 장치가 일관적 참여자라고 약속하지도 않습니다.

## 거짓 공유는 변수를 바꾸지 않고 비용을 바꾼다

CPU A가 `0x2000`의 카운터를 반복 갱신하고 CPU B가 `0x2008`의 별도 카운터를 갱신한다고 합시다. 둘 다 같은 라인에 있습니다. 변수가 논리적으로 독립이고 제대로 동기화되어도 그 라인의 쓰기 가능 소유권을 얻는 과정에서 CPU 간 일관성 트래픽이 발생할 수 있습니다.

많이 쓰이는 독립 데이터를 서로 다른 라인으로 분리하면 거짓 공유을 줄일 수 있지만, 추가 공간과 어딘가의 더 나쁜 국소성이라는 비용이 따릅니다. 이는 측정된 접근 패턴에 기반한 성능 설계이지 모든 객체를 자동으로 패딩해야 할 이유가 아닙니다.

다음 장은 주소 변환을 더합니다. 캐시 라인은 데이터를 담고 페이지 테이블은 주소 매핑을 기술합니다. 챕터 21의 TLB는 페이로드 바이트가 아니라 변환을 캐시합니다. 챕터 22~23에서 DMA 데이터가 오래된 문제에 대해 추론하기 전에 그 역할들을 분리해 두는 것이 필요합니다.

## 체크

1. 64바이트 라인일 때 어떤 범위가 주소 `0x203F`를 포함합니까?
   - A) `0x2000`–`0x203F`
   - B) `0x203F`–`0x207E`
   - C) `0x2040`–`0x207F`
   - Answer: A
   - Explanation: 라인 기준은 하위 6개 주소 비트를 지웁니다.

2. write-back 예제에서 따라오는 진술은? 모두 고르세요.
   - A) 더티 캐시 라인은 하위 메모리보다 새로울 수 있다.
   - B) CPU 일관성이 여러 명령어 증가를 자동으로 원자적으로 만든다.
   - C) 비일관적 관측자는 명시적 가시성 프로토콜이 필요하다.
   - Answer: A, C
   - Explanation: 데이터 사본 조정과 연산 수준 동기화는 서로 다른 문제를 풉니다.

3. 정렬된 주소 `0x2000`에서 시작하는 순차 루프가 4바이트 원소 40개를 읽고, 캐시는 처음에 비어 있으며 제거는 없습니다. 만나는 서로 다른 라인 수를 세세요. 시작 주소가 `0x203C`일 때도 반복하세요.

4. CPU가 9를 저장하고, 비일관적 장치가 나중에 하위 메모리에 12를 쓰고, 지연된 더티 CPU writeback이 9를 복원합니다. 타임라인을 그리고, 장치가 끝난 뒤 단순히 무효화만 하는 것이 왜 모든 이런 소유권 위반을 고치기에 너무 늦는지 설명하세요.

5. Research challenge: 선택한 플랫폼이나 커널의 DMA 문서를 살펴보세요. 장치가 일관적인지, 어떤 API가 필요한 동기화를 수행하는지 확인하세요. CPU 캐시의 존재만으로 올바른 유지보수 명령을 알 수 없는 이유를 설명하세요.

## 정확성의 경계

이 표는 하나의 단순한 write-back 캐시와 의도적으로 비일관적인 관측자를 사용합니다. 실제 캐시 수준, 정책, 라인 크기, 일관성 도메인은 다릅니다. 이식 가능한 드라이버에서 추측한 캐시 연산을 구현하지 말고 OS의 문서화된 DMA 인터페이스를 쓰세요.
